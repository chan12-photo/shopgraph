# 발표 뼈대와 예상 질문

- 기준: 계획서 7장(시연 장면 1~8, "발표의 중심", 659~686줄)과 8장(제안서 목차·작성 원칙, 688~736줄)
- 시연 장면의 숫자·순위는 모두 `[손계산 후 채움]`이에요. 값은 docs/demo_expected.md가 승인된 뒤에 그 파일에서 옮겨요.
- 예상 질문에는 답 문장을 쓰지 않았어요. 답의 근거가 되는 계획서 절과 코드 위치만 적었어요.

## 1. 발표 흐름 뼈대

발표의 중심 (계획서 660줄): "추천 시스템을 만들었다"보다, 구매 기록이 바뀔 때 그래프(간선 집계·소속)와 검색·추천 결과가 어떻게 따라 바뀌는지를 보여 주는 것.

| 순서 | 주제 | 담을 내용 (근거) |
|---|---|---|
| 1 | 문제 정의 | 쇼핑몰은 "누가 무엇을 샀나"라는 관계 데이터로 운영됨, 신규 고객은 이력이 없어 추천이 어려움 (계획서 8.1 1번, 690줄 부근) / 교수님 논의 반영: 의류로 범위 축소, 색상 재구매 가중치, 그룹 기반 신규 고객 추천 (계획서 3.2, 8.2) |
| 2 | 데이터 구조 | 고객·상품·구매 기록 원본 (계획서 5.1), 상품 = 모델·색상 = 옵션을 고른 이유 (계획서 5.1 끝 문단, 5.6) / ShopGraph 안의 원본·그래프·ID 카운터 (계획서 부록 B.1, graph.py:510) |
| 3 | 그래프 설계 | 노드 3종(그룹·고객·상품), 소속 간선·구매 간선, 간선 집계값 한 곳 저장, 가중치 = 색상 수 (계획서 5.2) / 인접 리스트를 고른 이유 (계획서 241줄) / 원본에서 그래프를 다시 만드는 방식 (graph.py:1083 rebuild, 1225 _build_graph) |
| 4 | 검색·추천 | S1~S4 (계획서 5.3.2, search.py) / 추천 규칙: 범위 확장, 상한 3, 정렬, 품절·이미 산 상품 제외 (계획서 5.3.3, search.py:372 recommend) / 6장 C07 예시로 한 단계씩 (계획서 6.3-1, docs/study/code_guide.md 4절) |
| 5 | 시연 | 아래 2절의 장면 1~8 |
| 6 | 검증 방법 | 테스트 먼저와 6장 손계산 기대값 (계획서 11.3.3 G2, 6장) / 무결성 검사와 고장 주입 (계획서 5.3.5) / 고장 검사: 일부러 틀린 구현을 테스트가 잡는지 (docs/verification/mutation_sweep.md) / 독립 검토 (계획서 11.3.1, docs/report_materials.md 4절) / 결함 기록 분류 A·B·C (계획서 11.3.9, docs/defects.md) |
| 7 | 한계 | 계획서 5.3.3 "알려진 한계"(341줄부터): 개인 취향 추정 안 함, 추천 품질 미검증, 상품 쪽 콜드 스타트, 인기 편향, 착용 대상 미고려, 다른 색 제안 안 함, 그룹 안 취향 차이 / 무결성 검사가 보장하지 않는 것 (계획서 385줄) |
| 8 | 제안서와 달라진 점 | 계획서 19장 (1224줄부터), 반영 대기 문안 (docs/verification/plan_pending.md 8번) / 3판 확장 문서 근거는 확장 단계 실제 수행 후 보충 (docs/report_materials.md 3절) |

## 2. 시연 장면 (계획서 7장, 입력 절차는 docs/verification/w11_scenes.md)

| 4 다시 추천 | 이미 산 상품이 빠짐 | 이미 산 상품 제외 (5.3.3) | 추천 항목 [손계산 후 채움] |
