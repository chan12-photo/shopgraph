## 1. 총평

**웹 API에서 실패한 등록 하나가 세션을 훼손한다.** JSON에 짝이 없는 UTF-16 서로게이트 `\ud800`을 이름으로 보내면 고객과 ID를 먼저 저장하고, 성공 응답을 UTF-8로 만드는 단계에서 400을 돌려준다. 같은 서버에서 그래프와 그룹 목록을 다시 조회해도 400이다. Chrome을 새로고침하면 그래프 노드가 0개이고 영문 인코더 오류와 “그래프를 불러오는 중입니다…”가 함께 남았다. 재고 색상 키로도 재현했다. 일반적인 메뉴 조작에서도 별도의 오류가 있다. 기본 시연 데이터에 여성 40세 고객 한 명을 등록하면 여성·40대 이상 칩 중앙을 눌렀는데 남성·20대가 선택된다.

기준 커밋은 `869f1f707292082ca81bfd07399a04b1ea403add`이다. 제공된 작업 경로가 존재하지 않아 `/Users/chan12/projects/shopgraph`에서 문서와 main 해시를 확인했다. 실험은 `git archive main`을 푼 `/private/tmp/shopgraph-audit.3YIxmz/base`와 여기서 파생한 사본으로 한정했다. 아래 파일·줄은 모두 이 커밋 기준이다. 신규 동작 결함, 계약 문구의 불일치, 고장을 일부러 넣은 실험을 구분했다. UI 세부 규칙에는 계획서 11.3.2의 UI0 D1~D4와 `docs/verification/ui0_design.md`의 11절 승인 기록을 함께 사용했다.

**기준 실행.** `python3 -B -m unittest` → Python 3.14.7 `Ran 192 tests in 15.601s` / `OK`. Python 3.11.15 → `Ran 192 tests in 16.142s` / `OK`. 최초 샌드박스 실행은 루프백 bind가 거절되어 184개 실행·29 errors였다. 위 두 수치는 로컬 bind를 허용하고 다시 실행한 원문이다. 중간의 `RuntimeError: after C07`은 테스트가 주입한 예외다.

**재현 명령.** 동봉 ZIP의 `scripts/` 파일을 새 임시 폴더로 복사하고 그 아래 `base/`에 위 커밋의 아카이브를 푼다. 다음 명령은 `base/`에서 실행한다. 각 표의 이름은 스크립트 안의 입력 키이거나 출력 줄을 찾는 문자열이다. 명시하지 않은 HTTP 사례는 127.0.0.1, 동적으로 할당한 포트, 실제 서버를 사용했다.

ZIP을 빈 임시 폴더에서 풀고 아래처럼 실행할 수 있다. 실제 저장소 경로는 첫 줄에만 쓴다.

~~~sh
repo=/Users/chan12/projects/shopgraph
# 현재 디렉터리는 압축을 푼 임시 폴더
cp scripts/*.py scripts/*.cjs .
mkdir base
git -C "$repo" archive 869f1f707292082ca81bfd07399a04b1ea403add | tar -x -C base
cd base
python3 -B ../differential.py
~~~

변이 재현은 lockfile과 맞는 설치본을 가리키는 환경변수 SHOPGRAPH_NODE_MODULES를 사용한다. Chrome 검사에는 기존 Playwright의 PLAYWRIGHT_MODULE과 실행 파일 CHROME_PATH를 지정할 수 있다. 저장소 원본 · node_modules · Chrome 프로필은 ZIP에 넣지 않았다.

## 6. 확인하지 못한 범위

- 운영체제는 macOS, 실제 브라우저는 Chrome 157 headless였다. Windows·Linux·Safari·Edge, 실제 프로젝터·화면 공유, 실제 사용자 환경의 발생 빈도는 확인하지 않았다. 자동 브라우저 검사는 서버의 별도 기본 브라우저 열기를 `BROWSER=/usr/bin/true`로 대체하고 자기 프로필로 접속했다.
- 차등 결과는 두 초기 데이터·두 시드·1,100개 변경에 한정된다. 공개 메서드로 만들 수 없는 임의의 Python 객체, 모든 손상 조합·모든 구매 수열을 망라하지 않는다. CLI 중단 위치 검사는 input 호출에서 EOF/KeyboardInterrupt 예외를 주입했다. 모든 운영체제에서 터미널 신호를 보낸 검사는 아니다.
- 수신 버퍼 실험은 정해진 부하와 정해진 대기 시간에서 정상 본문/응답이 끊길 수 있음을 보인 것이다. 절대적인 지연 최대값이나 실제 시연 데이터의 전송 실패율을 측정한 것은 아니다.
- 스냅샷 간 최신 선택 유지는 대표 GET 두 개와 변경 경로로 검사했다. 브라우저 여러 탭의 동시 편집 전체, 저장 도중 프로세스 강제 종료, 과거 커밋별 테스트 실행 원문, 모든 과거 검증 스크린샷은 확인하지 않았다. 11/07 기존 검토의 구조·일정·일반 대규모 레이아웃·ID 수명·W12 계산기 공유·죽은 함수 등은 별도 신규 결함으로 더하지 않았다.

**재현 자료.** ZIP 안 `scripts/reference.py`는 독립 계산기, `scripts/differential.py`는 고정 시드 실행기다. `logs/`에 두 버전의 HTTP 요청별 실제 결과, 차등·콘솔·Chrome·변이 로그를 동봉했다. 저장소에 새 파일을 쓰지 않았으며 원본 아카이브 사본·변이 프로젝트·브라우저 프로필은 전달물에서 제외했다.
