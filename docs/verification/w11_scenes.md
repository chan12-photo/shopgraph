# W11 시연 장면 입력 절차 (계획서 7장 장면 1~8)

- 날짜: 2026-11-01, 브랜치 w11-demo
- 이 문서는 **입력 절차만** 적는다: 어느 메뉴에서 무엇을 입력하는지, 그 장면에 쓰는 고객·상품 ID.
- **기대 결과(추천 순위·점수·가중치·결과 목록)는 적지 않았다.** 기대값은 사람이 data.py로 손계산하고 검산해서 docs/demo_expected.md에 적은 뒤 11.3.8 절차로 승인한다 (7장, 11.3.2 W11). W12 테스트는 그 파일에서만 기대값을 가져온다.
- 장면이 성립하는지 확인하려고 프로그램을 돌려 보지 않았다. 아래 "설계 의도"는 데이터를 그렇게 만들었다는 뜻이고, 실제로 그렇게 되는지는 손계산으로 확인해야 한다.
- 장면 1~8은 `python main.py`를 한 번 실행해 처음 상태(data.py)에서 차례로 진행한다. 앞 장면의 변경이 뒤 장면의 상태가 된다.
- 손계산 뒤 정할 값은 이름으로 적었다: `C_new`(장면 2에서 등록하는 고객), `P_top`(장면 2 추천 1위 상품), `P_top6`(장면 6 직전 C_new 추천 1위 상품), `C_new7`(장면 7에서 등록하는 고객). 고객 ID는 B.1 발급 규칙(초기 데이터의 가장 큰 번호 + 1, 등록 순서대로)으로 정해지므로 손계산 때 함께 확인한다.

## 장면 1. 그룹별 고객 트리 → 데이터 구조 소개

| 순서 | 메뉴 | 입력 |
|---|---|---|
| 1 | `메뉴 선택` | `5` (PRINT) |
| 2 | `번호 선택` | `1` (그룹별 고객) |

- 쓰는 ID: 그룹 8개 전체 (고객·상품 입력 없음)
- 설계 의도: 남성·10대(G-M-10)에 소속 고객이 없고, 여성·40대 이상·남성·40대 이상은 인원이 적다

## 장면 2. "25세 여성" 신규 고객 등록 → 여성·20대 연결 → 즉시 추천 + 근거

| 순서 | 메뉴 | 입력 |
|---|---|---|
| 1 | `메뉴 선택` | `1` (CREATE) |
| 2 | `번호 선택` | `1` (고객 등록, 등록 직후 추천) |
| 3 | `이름` | `하람` (기존 고객과 겹치지 않는 이름) |
| 4 | `성별 (1 남 / 2 여)` | `2` |
| 5 | `나이` | `25` |

- 쓰는 ID: 새 고객 `C_new`, 그룹 G-F-20(여성·20대, 소속 C04~C11)
- 손계산할 것: C_new의 그룹 연결, K=3 추천 결과(범위·점수·구매자 수·근거·구매 가능 색상), `P_top`

## 장면 3. 추천 1위 상품을 두 가지 색상으로 구매 → S1에서 가중치 2 확인

| 순서 | 메뉴 | 입력 |
|---|---|---|
| 1 | `메뉴 선택` → `번호 선택` | `1` → `3` (구매 등록) |
| 2 | `고객 ID` / `상품 ID` | `C_new` / `P_top` |
| 3 | `색상` / `수량` / `구매일` | `P_top`의 재고 있는 색상 중 하나 / `1` / `2026-10-30` |
| 4 | `메뉴 선택` → `번호 선택` | `1` → `3` (구매 등록) |
| 5 | `고객 ID` / `상품 ID` | `C_new` / `P_top` |
| 6 | `색상` / `수량` / `구매일` | 3번과 **다른** 재고 있는 색상 / `1` / `2026-10-31` |
| 7 | `메뉴 선택` → `번호 선택` | `2` → `4` (S1 고객이 산 상품) |
| 8 | `고객 ID` | `C_new` |

- 쓰는 ID: `C_new`, `P_top`. 두 색상은 손계산 때 P_top의 색상 목록에서 정한다 (data.py의 상품은 색상 2~4개이고, 장면 2 시점에 전부 품절인 상품은 추천에 나오지 않는다)
- 손계산할 것: 구매 등록 줄의 가중치, S1 화면

## 장면 4. 다시 추천 → 이미 산 상품이 빠지고 다음 순위가 올라옴

| 순서 | 메뉴 | 입력 |
|---|---|---|
| 1 | `메뉴 선택` | `6` (RECOMMEND) |
| 2 | `고객 ID` | `C_new` |
| 3 | `추천 개수 K` | Enter (기본 3) |

- 쓰는 ID: `C_new` (`P_top`이 결과에서 빠지는지 보는 장면)
- 손계산할 것: K=3 추천 결과

## 장면 5. 다른 여성·20대 고객이 특정 상품을 세 가지 색상으로 구매 → S4 그룹 인기 순위 변화

| 순서 | 메뉴 | 입력 |
|---|---|---|
| 1 | `메뉴 선택` → `번호 선택` | `2` → `7` (S4 그룹 인기 상품) |
| 2 | `그룹` / `개수` | `2` (여성·20대) / Enter (전체) |
| 3 | `메뉴 선택` → `번호 선택` | `1` → `3` (구매 등록) |
| 4 | 고객·상품·색상·수량·구매일 | `C09` / `P07` / `블랙` / `1` / `2026-10-30` |
| 5 | `메뉴 선택` → `번호 선택` | `1` → `3` |
| 6 | 고객·상품·색상·수량·구매일 | `C09` / `P07` / `그레이` / `1` / `2026-10-30` |
| 7 | `메뉴 선택` → `번호 선택` | `1` → `3` |
| 8 | 고객·상품·색상·수량·구매일 | `C09` / `P07` / `네이비` / `1` / `2026-10-31` |
| 9 | `메뉴 선택` → `번호 선택` | `2` → `7` |
| 10 | `그룹` / `개수` | `2` / Enter |

- 쓰는 ID: C09 단비(여성·20대, data.py에서 P07을 사지 않음), P07 밴딩 슬랙스(색상 4가지 블랙·그레이·베이지·네이비, 모두 재고 있음), 그룹 G-F-20
- 손계산할 것: 구매 전·후 S4 순위. **순위가 실제로 바뀌는지는 손계산으로 확인해야 한다.** 바뀌지 않으면 고객·상품 선택을 사람이 다시 정한다 (이 문서는 고칠 수 있음)

## 장면 6. 현재 추천을 보여 준 뒤, 그 1위 상품의 재고를 전부 0으로 → 다시 추천

| 순서 | 메뉴 | 입력 |
|---|---|---|
| 1 | `메뉴 선택` | `6` (RECOMMEND) |
| 2 | `고객 ID` / `추천 개수 K` | `C_new` / Enter |
| 3 | `메뉴 선택` → `번호 선택` | `3` → `2` (상품 수정) |
| 4 | `상품 ID` | `P_top6` |
| 5 | `상품명` / `종류` / `스타일` / `가격` | Enter / Enter / Enter / Enter (그대로) |
| 6 | `색상별 재고` | P_top6의 **모든 색상**을 그대로 적고 수량만 0 (예: 색상이 A·B·C면 `A=0, B=0, C=0`). 색상을 빼면 "색상 삭제"가 되어 구매 기록이 있는 색상은 거절된다 (B.3) |
| 7 | `메뉴 선택` | `6` (RECOMMEND) |
| 8 | `고객 ID` / `추천 개수 K` | `C_new` / Enter |

- 쓰는 ID: `P_top6`(장면 5까지 진행한 상태에서 C_new 추천 1위, 손계산으로 확정), `C_new`
- 발표 설명 메모: S4에서 P07은 2위(1위 P03)지만 C31은 P03을 장면 3에서 이미 사서 추천에서는 P07이 1위
- 손계산할 것: 품절 전 추천 결과, P_top6, 재고 0 뒤 추천 결과

## 장면 7. 소속 고객·구매가 없는 그룹(남성·10대) 고객 등록 → '남성 전체'로 넓혀 추천

| 순서 | 메뉴 | 입력 |
|---|---|---|
| 1 | `메뉴 선택` → `번호 선택` | `1` → `1` (고객 등록) |
| 2 | `이름` / `성별` / `나이` | `새싹` / `1` / `15` |

- 쓰는 ID: 새 고객 `C_new7`, 그룹 G-M-10(data.py에서 소속 고객 0명), 같은 성별 그룹 G-M-20·G-M-30·G-M-40+
- 손계산할 것: 추천 결과의 범위 표시, 넓힘 안내 줄("다른 고객이 없어 '남성 전체'로" 틀, W8b 승인 형식), 점수 비교 안내 줄이 나오는지
