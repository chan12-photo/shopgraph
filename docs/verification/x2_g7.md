# X2 검증 책임 분리 — Claude 구현·자체 확인 (11/16)

검토 구분: Claude 구현, Claude 자체 확인. 같은 세션의 확인이므로 독립 검토가 아니다. 독립 확인은 다른 도구(Codex)의 새 세션이 하고, 판정과 승인은 찬일이 한다.

## 상태와 기준

- 작업 브랜치: `x2`. 기준: `x1-guri` `830ae78`(전체 테스트 291개). main은 `a9c42ad` 그대로다.
- 확장성 변경안 v3 5.5(검증 책임 분리)·6장 E1·E9·7.1 X2 행을 따랐다. 동작을 바꾸지 않는 이동이다.
- 테스트 파일(tests/) 변경 0줄. 새 테스트도 추가하지 않았다(v3 7.1 통과 기준).
- 아래 실행은 모두 Claude의 Linux 작업 사본에서 했다(실제 소켓 사용). 찬일 터미널(macOS)의 전체 실행과 브라우저 검사는 이 문서를 쓴 시점에는 아직 하지 않았다.

## 무엇을 바꿨는가

1. 새 모듈 `validation.py`: graph.py에 있던 입력 검증 함수 15개와 검증용 상수를 옮겼다. 함수 본문은 이름만 바꾸고 그대로다.
2. `graph.py`: 옮긴 것을 validation.py에서 가져온다. 모듈 안에서는 예전 이름(`_clean_text` 등)으로 받아 쓰므로 `ShopGraph` 클래스 본문은 한 글자도 바뀌지 않았다. 1367줄 → 1025줄, validation.py 392줄.
3. 의존 방향: graph.py → validation.py 한 방향뿐이다. validation.py는 표준 라이브러리만 가져온다.
4. `docs/verification/x0_bench.py`(진단 스크립트, 테스트 파일 아님): 측정 중 ID 형식을 6/6/7자리로 바꿔 끼우는 대상에 `validation.ID_PATTERNS`를 더했다. 형식 검사가 이 값을 읽기 때문이다. 복구 확인도 이 값을 함께 본다. 측정 항목·데이터 생성·출력 형식은 그대로다.
5. 계획서·CLAUDE.md에 넣을 문안은 plan_pending.md 끝 "X2 반영 문안"에만 적었다.

## 옮긴 것과 남긴 것

| 종류 | validation.py로 옮김 (새 이름 ← graph.py의 옛 이름) |
|---|---|
| 공개 상수 | KINDS, STYLES, GENDERS, AGE_BANDS (이름 그대로) |
| 검증용 상수 | ID_PATTERNS ← _ID_PATTERNS, NAME_MAX ← _NAME_MAX, COLOR_MAX ← _COLOR_MAX, QTY_MIN ← _QTY_MIN, QTY_MAX ← _QTY_MAX, GENDER_VALUES ← _GENDER_VALUES |
| validation.py 안에서만 쓰는 상수 | _DATE_PATTERN, _CUSTOMER_KEYS, _PRODUCT_KEYS, _PURCHASE_KEYS (이름 그대로) |
| 함수 13개 | value_error, check_date, check_int, clean_text, check_choice, clean_stock, clean_customer, clean_product, clean_purchase, clean_purchase_color, clean_records, check_purchase_refs, clean_query (모두 옛 이름에서 앞의 _만 뗌) |
| validation.py 안에서만 쓰는 함수 2개 | _check_record_id, _check_record_shape (이름 그대로) |

graph.py에 남긴 것: `ShopGraph`, `id_sort_key`, `_ID_DIGITS`, `_next_number`, `_group_id_for`, `_aggregate_edges`, `_lookup`, 그룹·추천 상수(GENDER_LABELS, GROUP_IDS_BY_GENDER, GROUP_IDS, GROUP_LABELS, WEIGHT_CAP, K_DEFAULT, K_MAX).

판단 기록:
- validation.py의 이름에서 `_`를 뗀 이유: 다른 모듈(graph.py)이 가져다 쓰는 이름이라 CLAUDE.md의 "다른 모듈에서 내부 속성(_) 쓰기 금지"와 맞춘 것이다. graph.py는 `from validation import clean_text as _clean_text`처럼 받아, graph 모듈의 공개 이름은 늘지 않는다.
- AGE_BANDS·GENDERS를 옮긴 이유: 나이 범위와 성별 값 검증이 이 상수를 읽는다. validation.py가 graph.py를 가져오면 순환 import가 되므로 정의를 validation.py에 두고 graph.py가 다시 내보낸다.
- `_lookup`(ID로 레코드 찾기)과 `_group_id_for`(그룹 계산)는 ShopGraph의 내부 표·그룹 상수를 다루므로 graph.py에 남겼다. 둘 다 `value_error`만 가져다 쓴다.
- `graph._ID_PATTERNS`는 graph.py의 코드가 더는 읽지 않는다. tests/test_bench.py가 측정 뒤 원래 값으로 돌아왔는지 이 이름으로 확인하므로 이름만 남겼다(테스트 파일 0줄 변경 조건).
- search.py의 `_value_error`는 합치지 않았다(W10a 구조 유지).

다시 내보낸 공개 이름: graph 모듈에서 `_`로 시작하지 않는 프로젝트 이름은 X2 전후가 같다(AGE_BANDS, GENDERS, GENDER_LABELS, GROUP_IDS, GROUP_IDS_BY_GENDER, GROUP_LABELS, KINDS, K_DEFAULT, K_MAX, STYLES, ShopGraph, WEIGHT_CAP, id_sort_key). 달라진 것은 graph.py가 더는 가져오지 않는 표준 라이브러리 이름 3개(`Callable`, `datetime`, `re`)뿐이며, 저장소에서 `graph.re` 등을 쓰는 곳은 없다.

## 미확인 항목·남은 한계

1. 찬일 터미널(macOS)에서 Python 3.11·3.13·3.15 전체 테스트를 아직 돌리지 않았다.
2. 브라우저 검사(ui5·ui9b)를 돌리지 않았다. frontend와 web.py는 바꾸지 않았고 웹 테스트는 전체 테스트에 포함돼 통과했지만, 브라우저 검사 통과로 적지 않는다.
3. 독립 확인 전이다. 구현과 이 확인을 같은 Claude 세션이 했다.
4. X2는 구조 정리다. 변경 1건마다 전체를 다시 만드는 구조는 그대로라 처리 속도는 달라지지 않는다. 원본 저장 분리와 부분 갱신(X3a 이후)은 이번 제출 범위가 아니다.
5. X1에서 기록만 남긴 A50·A51은 그대로다. `_check_record_id`는 본문을 바꾸지 않고 옮겼다.
6. `graph._ID_PATTERNS`는 테스트 호환용 이름으로만 남아 있다. 측정 도구를 정식 ID 규칙으로 새로 만들면(작업 C) 정리할 수 있다.
