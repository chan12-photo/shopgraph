# X1·X2 뒤 측정과 전후 비교 (11/16)

검토 구분: Claude 구현·작성. 숫자는 모두 찬일 Mac 터미널에서 실행한 결과 파일(xc_results.json)에서 스크립트로 뽑았다. 같은 세션의 확인이므로 독립 검토가 아니다. 판정과 승인은 찬일이 한다.

이 문서는 두 번째 판이다. 첫 판은 실행 결과를 본 뒤에 기준 없이 두 실행을 판단에서 빼고 "같은 수준"이라고 적었고, Codex 독립 확인에서 "측정 Codex 확인 불가"(높음 1건, 중간 2건)를 받았다. 첫 판은 저장소에 올리지 않았다. 이 판은 판정 기준을 먼저 정하고 새로 잰 15회로만 판정하며, 그 전에 잰 값은 하나도 빼지 않고 참고로 싣는다.

## 한 줄 요약

미리 정한 기준으로 판정한 결과, X1(가변 ID·숫자 정렬) 뒤 5개 항목이 느려졌다: 추천 K=3 +16.3%, 추천 K=10 +18.3%, S4 +19.1%, 전부 품절 추천 +20.6%, 무결성 검사 +55.2%. 생성과 변경 9종은 X1 전후 차이가 +0.1%~+1.9%로 관측됐고 이 측정으로는 느려졌는지 가릴 수 없다(구매 단건 조회는 +5.3%이나 방향이 엇갈려 가릴 수 없다). X2(검증 분리) 전후는 구매 단건 조회를 뺀 14개 항목이 -1.6%~+1.5%, 구매 단건 조회(0.007ms 수준)가 -5.6%로 관측됐고, 15개 항목 모두 짝의 방향이 엇갈려 가릴 수 없다. 변경 1건마다 전체를 다시 만드는 구조는 그대로라 30만 건에서 변경 1건은 약 0.3초다.

## 무엇을 만들었는가

새 도구 `tools/bench.py`: 운영 ID 규칙 그대로(C01·P01·T001부터 자릿수 확장) 데이터를 만들어 잰다. graph·validation의 상수를 바꿔 끼우지 않고 ShopGraph 공개 메서드와 graph 공개 상수만 쓴다. 측정 항목·순서·시간 구간·난수 순서는 X0 진단 스크립트와 같다. 환경 정보 명령(sysctl·git)이 막힌 곳에서도 끝나도록 실패 값을 "확인 불가"로 남긴다. 테스트 4개(tests/test_bench_tools.py)를 추가해 전체 295개다. 운영 코드는 바꾸지 않았다.

## 판정 기준 (판정 측정 전에 정함)

아래 기준은 참고 실행 14회(뒤의 "참고" 절)의 결과를 본 뒤, 판정 측정 15회를 실행하기 전에 정했다. 판정에는 뒤에 잰 15회만 쓴다.

1. 판정 측정 15회를 모두 쓴다. 무결성 확인이 False이거나 실행이 실패하면 값을 골라 빼지 않고 묶음 전체를 다시 한다. (실제로는 15회 모두 정상이라 다시 하지 않았다.)
2. 항목별 각 버전의 대표값은 5회 실행 중앙값의 중앙값이다.
3. X1 효과는 B를 A와, X2 효과는 C를 B와 같은 라운드끼리 짝지어 본다(짝 5개).
4. 짝 5개의 방향이 모두 같고 대표값 차이가 5% 이상일 때만 "느려짐"·"빨라짐"이라고 쓴다. 그 밖은 "가릴 수 없음"이다. "가릴 수 없음"은 같다는 뜻이 아니다.
5. 11/07 X0 값과 참고 실행 14회는 모두 싣되 판정에 쓰지 않는다.

## 느려진 까닭 (확인한 것과 추정)

확인한 것: 느려짐은 A와 B 사이, 즉 X1 커밋 범위(a9c42ad→830ae78)에서 생겼다. 이 범위에서 운영 코드는 graph.py와 search.py만 바뀌었다.

추정: X1에서 ID를 문자열 순이 아닌 숫자 순으로 정렬하려고 추천의 동료·동점 정렬과 무결성 검사의 정렬이 ID마다 `id_sort_key`로 (종류, 번호, 문자열) 키를 만든다. 느려진 다섯 항목이 모두 이 정렬을 거치고, 느려짐으로 판정되지 않은 생성·변경 경로에는 이 정렬이 없다. 다만 X1에는 ID 형식 검사와 발급 방식 변경도 들어 있고, 정렬 키만 따로 떼어 Mac에서 잰 실행은 결과 파일에 없다. 그러므로 정렬 키는 유력한 후보일 뿐 원인으로 확정하지 않는다.

## 남은 한계

1. 시드 1의 합성 데이터, 구매 30만 건, Mac 한 대, Python 3.14.7의 측정이다. 실제 쇼핑몰 분포·더 큰 규모·동시 요청·다른 컴퓨터는 재지 않았다. 웹 계층과 브라우저 렌더링도 포함하지 않는다.
2. 버전마다 5회, 실행 1회 안의 반복은 3~5회다. 5% 기준과 "짝 5개 모두 같은 방향"은 이 문서가 정한 실용 기준이며 통계 검정이 아니다. 5%보다 작은 차이는 이 측정으로 가릴 수 없다.
3. 판정 기준은 참고 실행 14회의 결과를 본 뒤에 정했다. 판정 측정 15회의 결과를 보기 전에 정했고, 정한 뒤에는 바꾸지 않았다. 다만 기준을 먼저 정했다는 시간 순서는 이 문서의 서술과 작업 대화 기록으로만 남아 있고, 저장소에는 측정이 끝난 뒤의 커밋만 있어 저장소만으로는 확인할 수 없다.
4. 변경 1건마다 원본에서 그래프 전체를 다시 만드는 구조는 그대로다. 한 건씩 대량으로 넣는 작업에는 맞지 않는다. 바뀐 부분만 고치는 방식은 X3a 이후 범위이며 이번 제출에서 하지 않는다.
5. 느려진 추천·무결성 검사를 다시 빠르게 하는 작업은 하지 않았다. 시연 규모(고객 7명 안팎)에서는 재지 않았다.
6. 이 판의 독립 확인(Codex, 7f5b800 대상): 판정 표 135칸·참고 표 276칸 재계산에서 틀린 칸 0, 15회 모두 사용·실행 순서·각 버전 HEAD 일치, 참고 14회 누락 없음. 지적 2건(X2 범위 요약에서 구매 단건 조회 -5.6%를 빠뜨림, "느려지지 않은"이라는 과한 표현)을 [X2 보완]에서 고쳤다. 고친 문장 자체는 다시 확인받지 않았다.
